# 窗口结构（每行/每栏的名字）

> 用途：以后要改界面时，**先说栏位名，再说改什么**，就不必靠"最上面那一行""波形下面那条"来描述。
> 每个栏位在 `saltlrc/web/index.html` 里都有 `data-bar="<名字>"`，
> 并有 `id` 可以直接在 CSS / JS / 测试里引用。
>
> **改名要连这四处一起改**：`index.html` 的 `id`/`data-bar`、`style.css`、`studio.js`、
> `tests/test_web_pages.py::test_every_bar_has_a_stable_name`（那里逐个钉着名字，
> 少一个测试就红）。**不要改已经在用的 `id`** —— 代码按 `id` 取元素，
> 改名等于把控件接空（`#message` 曾被我改名成 `#appStatus`，`say()` 当场失效）。

### ⚠️ `main` 的网格只认一个变量（v0.24.3）

`main` 是**两栏或三栏的网格**，而列定义**只有一个写者**：CSS 里的 `--split-left`。

| 窗口宽度 | 列 | 第 2 列是 |
|---|---|---|
| 基础（窄屏） | `min(var(--split-left),50%)` + 编辑器 | 编辑器 |
| ≥1250px | `min(var(--split-left),50%)` + `10px` + 编辑器 | **`#splitter` 分栏把手**（10px 那条轨） |
| ≤1249px | `#splitter{display:none}` | 把手不再是网格项 → 回到两栏 |

**铁律：页面只许 `style.setProperty('--split-left', …)`，不许内联写 `grid-template-columns`。**
内联样式**恒胜样式表、`@media` 管不了它** —— 一写内联，窄屏时列数（3）与网格项数（2）就对不上，
编辑器会掉进那条 10px 的轨里，整个界面挤成一条（v0.24.3 修的真 bug）。
`test_web_pages.py` 有一条**全站扫描**守着它：`@media` 里管过的属性不许再被内联写。

> **`appNav`（第 2 条）就是"顶部 dock"**：`position:sticky;top:0`，页面滚动时它不动，
> 所以是**始终可见的按钮条**。它的分工（v0.16.0 起）是
> **"这条流水线的入口与出口都放这里"**：导入 / 打开 / 帮助 / 设置 / 保存工程 / 批量导出 /
> 输入编码 / 曲库页；**编辑坞只放"改这首歌的内容"**（编辑 · 检查 · 翻译 · 导出歌词）。

### `transportBar` 里两条容易改坏的规则（v0.18.0）

1. **倍速（`#speed`）**：档位只在 `studio.js` 的 `SPEEDS` 里定义，下拉选项由
   `fillSpeedOptions()` 生成 —— **不要在 HTML 里再写一遍 `<option>`**（有断言钉着）。
   `applySpeed()` 必须**同时**写 `playbackRate` 与 `defaultPlaybackRate`：
   换音源时浏览器把前者重置回后者，只写一个就会"每选一首歌倍速悄悄变回 1×"。
2. **播放位置（`playbackMark` + `segmentStart`）**：「下次按播放从第几秒开始」由
   `playbackAnchor()` 一处回答。两个槽位各管一个问题，别合并：
   `playbackMark` = 位置（暂停点 / 显式指定的点），`segmentStart` = **这一段**的起点。
   写位置的一共 7 处（含函数定义），每处都带原因字符串（`'定位到'`/`'暂停于'`…），
   `Ctrl+Shift+T` 里能看到。**新增"跳转/试听"类按钮时必须同时记位置**
   （并且传 `freshSegment=true` —— 那表示"用户换了个位置"，反复播放的那一段要作废）。
   行为在 `tests/web_transport_check.js`（41 项）。
3. **两条播放规则的优先级写死在 `playbackAnchor()` 里：反复播放优先。**
   「反复」（`#repeat`，走带条上的实时开关，与设置里的 `#setRepeat` 是同一个值）
   和「从暂停点继续」（`#setResume`）面对的是同一个手势（暂停后按播放），
   **必然冲突**：开着「反复」时回到这一段起点，「从暂停点继续」不参与判断；
   关掉「反复」就回到那条开关的行为。**不要把这个判断复制到第二处**——
   两条规则各判一次就是"同一件事两处各算一遍"的老病。

> `lyricPreview` 的高度是**写死的**（`style.css` 里 `#preview .prow.*` 各自固定 height，
> 合计 14+18+6+78+6+20+18+14 = **174px**）。**没有歌词时也不许变矮、长句也不许撑高** ——
> 否则下面的波形会跟着上下跳。要改高度就改那三行 `height`，别改成 `min-height`。

## 三、`editDock` 编辑坞（编辑区里的一行）

**`appNav`（顶部 dock）才是"始终可见"的那条**；`editDock` 只属于「波形编辑」页。

```
┌ 改结构 ─────────────────────┬ 检查 ─────────────┬ 翻译当前已加载的歌词 ──────────┐
│ 撤销 重做 添加行             │ 检查歌词          │ AI 翻译本行                    │
│ 整体偏移[0] 应用 ms          │                   │ 翻译全曲缺失行                 │
└─────────────────────────────┴──────────────────┴───────────────────────────────┘

保存工程… 与 ▢工程内嵌音频 已移到顶部 dock（v0.16.0）；
**导出歌词… 也搬去顶部 dock（v0.23.3）** —— 见下面那条 ⚠️。
```

> 组与组之间用 `<span class="sep">` 细线分隔（`.spacer` 把左半和右半顶开）。

### ⚠️ 「AI 翻译」两个按钮：作用与位置

- **作用**：翻译**当前已加载的歌词**（走 `/api/translate`：不联网找歌词、不碰音频）。
  - 「AI 翻译本行」= 翻译正在编辑的那一行（先播放定位或点表格选中一行）；
  - 「翻译全曲缺失行」= 只补上全曲里还没有翻译的行。
- **位置**：**紧跟「检查歌词」**（同属"只跟这首歌有关"那一栏）。
  - 它是唯一的例外：**不要因为"分组更顺"就把它挪到别处**，
    顺序由 `test_web_pages.py` 里
    `test_the_translate_buttons_the_import_and_export_entries_live_in_the_right_bars` 钉着。
  - `title` 里写着"翻译当前已加载的歌词"。

### ⚠️ 导入/导出的入口必须在顶部 dock（v0.23.3）

`#export` 放在 `#editDock` 里时，editDock **只存在于「波形编辑」标签页**
（`#wavePane`）—— 切到另外两个标签页，这个按钮**不在屏幕上**，
表现就是"导出歌词失效 / 点了没反应"。

规矩（断言钉住）：**导入/导出/保存**（`pickLibrary` · `files` · `folder` · `save` ·
`export` · `zip`）→ `#appNav`；**改这首歌的内容**（撤销/重做/添加行/整体偏移/检查/翻译）→
`#editDock`。**同一件事不许在两处各放一个按钮。**

> `.saltproj` 在 v0.24.4 起有了**第二个入口：在资源管理器里双击**（文件关联）。
> 它走的是**启动参数**（`--open`），不进页面控件表 —— 判据是"这一条不需要在界面上找得到"，
> 因为它根本不在界面里发生。路径从本进程命令行来，页面只问 `/api/pending-open` 要字节。

### 顶部 dock（`appNav`）与编辑坞的分工

| 放哪 | 判断标准 | 例子 |
|---|---|---|
| **`appNav`（顶部 dock）** | **流水线的入口与出口**，且希望**始终够得着** | 从曲库导入 / 添加·打开 / 导入文件夹 / 载入示例 / 帮助 / 设置 / 保存工程… ▢工程内嵌音频 / **导出歌词…** / 批量导出 ZIP / 输入编码 / 曲库页 |
| **`editDock`（编辑区）** | 只跟**当前这首歌的内容**有关 | 撤销 / 重做 / 添加行 / 整体偏移 / 检查歌词 / **AI 翻译本行 · 翻译全曲缺失行** |

### `editDock` 各组的说明

- **撤销 / 重做 / 添加行 / 整体偏移** —— 改这首歌的结构与时间；
- **检查歌词** —— 跑 `/api/validate`，把**导出器会拒绝的问题提前列出来**，
  结果显示在「检查与工程」页的「需要处理的问题」里（每条可点「定位」跳到表格那一行）；
  **有错误时状态行会出声并自动切到那一页**（结果不在本页，不出声就又是一个"点了没反应"的按钮）；
- **导出歌词…** —— **在顶部 dock**（v0.23.3 搬过去的，理由见上）；另存为 `.lrc / .yrc`，
  **只有歌词、不含音频**；内容是**当前的 L0 文档**，不去磁盘上找原始歌词文件；
  对话框**从这首歌自己的文件夹打开**（拿不到就用「文档」）；
- **AI 翻译本行 / 翻译全曲缺失行** —— 见上面那条 ⚠️（作用：翻译当前已加载的歌词）；
- **保存工程…  ▢工程内嵌音频** —— **在顶部 dock**（属流水线出口）；开关只作用于它。

### ⚠️ 每一次"歌词编辑"必须同时做到四件事（v0.22.1）

表格里的文字框、每行的「＋插入 / 删除 / 交换」、逐字编辑器、AI 翻译、贴唱应用……
**凡是改动 `item.document` 的操作**，都必须：

1. **改文档**；2. **`remember(item, '标签')` 记一步历史**；3. **落盘**（`remember` 内部的
`persist()` → `Project.sync()`，所以只要走了 ② 就自动有 ③）；4. **`refresh()` 重绘**。

**②是唯一出口，第一个参数必须是歌曲条目。**
`remember(item = current(), label = '编辑', next = null)` 三个参数都有默认值，
把标签写到第一个参数上**不报错**，只在下一行抛一个与原因无关的 TypeError ——
结果是"文档改了、历史没记、工程没落盘、界面没重绘"。
现在两层守着：`history.js` 的 `assertEntry()`（运行时出声）+
`tests/test_web_pages.py` 的静态断言（改代码时拦）；
行为侧由 `tests/web_insert_e2e_check.js` 验（改一次文字 → 历史里多一步 → 能撤销 → 不抛异常）。

**行号类状态（`anchorRow` / `wordIndex`）会随文档形状失效**：撤销/重做、换歌、
迟到的导入结果都会改行数。读它们之前先判边界（`insertRow` 越界就当"没选中"）；
逐字编辑器另有一道形状凭据（`wordOpened`，和贴唱的 `fit.snapshot` 同一套），
对不上就拒绝写入，**绝不把字写进别的行**。

**删到一行不剩**时 `#rows` 里会放一条 `tr.emptyRow`（整行提示，不可点）——
空状态必须给下一步，否则用户以为界面坏了。

### 可选项统一是"开关"

`style.css` 给 `input[type=checkbox]` 写了开关样式（滑轨 34×18 + 圆点），
**一处规则覆盖全部页面与弹窗**；以后新增的 `type=checkbox` 可选项自动就是开关。

**例外（显式保留方框，有断言钉住）**：`#queue` / `.pick` / `#matchCandidates`
—— 那是**"挑条目"不是"开关"**。要新增例外，同时改 CSS 与那条断言。
（`#proposals` 曾是第四个例外；贴唱列表现在只有一个「试听」按钮，勾选框没了，
相关的 CSS 已随 v0.22.0 的重构删掉。贴唱的行样式在 `#fitList .proposal`。）

> 自绘控件时注意**通用规则**：`input,textarea{padding:8px}` 也会命中勾选框，
> 必须显式 `padding:0`，否则开关被撑成 50×34。

### 新增按钮放哪

1. 先问 **"它是应用级的、还是只跟当前这首歌有关"** → 顶部 dock / 编辑坞；
2. 再放进该栏的**对应组**，不要平铺；跨组用一个 `<span class="sep">`；
3. **唯一的人为例外**：`AI 翻译` 两个按钮固定在「检查歌词」之后，
   **不要因为"分组更顺"就把它挪走** —— 那条顺序有断言钉着。
   （导出按钮搬进 dock 之后，
   改成了"同栏语义相邻"。改它的位置之前先读 `docs/CHANGELOG.md` v0.23.3。）

## 四、改界面前的自检清单

1. **动的是哪一条栏？**（用上面的名字说）
2. **会不会让某条栏的高度随内容变？** —— 会的话就不能这么做（见 `lyricPreview`）。
3. **有没有引入第二个"同一件事"的控件？** —— 有就删掉重复的那个。
4. **有没有改已经在用的 `id`？** —— 改了要全局搜一遍（`grep -rn "id" saltlrc/web/*.js`）。
4b. **有没有挪动被点名的位置？** —— `AI 翻译` 要留在编辑坞里、紧跟「检查歌词」；
    **导入/导出的入口必须都在顶部 dock**（`#editDock` 跟着「波形编辑」标签页消失，
    所以它里面不能有任何"入口/出口"类按钮）。
5. **这个属性有没有被 `@media` 管过？** —— 有的话**不许内联写它**（内联压过 `@media`，
   窗口一缩放布局就错乱；v0.24.3）。要让页面调，就用**一个 CSS 变量**，样式表里读它。
6. 跑 `python -m unittest discover -s tests -p "test_*.py" -t tests`：栏位名、顺序、接线、网格都在里面钉着。

## 五、`alignPane` 识别与对齐 = 智能贴唱（v0.22.0 重建）

一句话：**识别方式与对齐逻辑一起重写成一层（`saltlrc/fit.py`），页面上只剩一个按钮**。
旧的三套做法（分析当前音频 / 整首行首对齐 / 行内逐字细化）是同一件事的三种切法，
连它们的控件一起收掉了 —— 那是 v0.21.0 之前的事，**别加回来**（有断言挡着）。

| 控件 | `id` | 干什么 / 注意什么 |
|---|---|---|
| 贴唱轨道 | `sourceTrack` | 自动 / 主轨 / 翻译轨（`auto` 由后端 `source_track()` 判定） |
| 最大移动量 ms | `maxShift` | 单个句首最多挪多少，**真的会传给后端**（`max_shift`） |
| 引擎说明 | `fitEngineState` | 只陈述事实：本机能量贴唱永远可用（不下载任何模型） |
| 语言 | `languages` | 只读显示（`/api/language` 的结果）；v0.22.0 起不再有任何下拉 |
| 智能贴唱 | `smartFit` | **唯一入口**：`/api/align/fit` 一次拿到整首提案 + 贴好的文档 |
| 预览 | `fitPreview` | **默认开**。开着时时间轴/表格跟随/播放都按**贴后**那份走（`timelineGroups()`） |
| 应用贴唱 | `fitApply` | `remember(item, '智能贴唱', fitted)` → 可撤销；会先比对 `fit.snapshot`，**改过歌词就拒** |
| 丢弃 | `fitDiscard` | `clearFit()`，文档一个字不动 |
| 保存分析结果 | `saveTranscript` | 走 `/api/save-as`（`suffix: '.json'`）—— **不许用页面的 `download()`** |
| 状态行 | `fitState` | **原样写出服务端的 `notice`**；失败时写"贴唱没做成：<原因>" |
| 汇总栏 | `fitReport` | `fitSummary()`：起点数 / 贴到 / 置信偏低 / 保持原时间 |
| 结果列表 | `fitList` | 逐行「原来在哪 → 贴到哪 [标签] 为什么」+ 每行一个**试听**按钮 |

**三条只许有一个权威的事**（都钉在 `tests/web_align_check.js`）：

1. **`timelineGroups(item)`** —— 「按时间找行」的唯一来源（`preview()` 与 `activeRow()` 都调它）。
   句首有两个来源（原稿 / 贴唱提案），一旦一个函数读一个，就会出现
   "高亮在第 3 行、表格钉在第 4 行"。
2. **`fit.snapshot`** —— 贴唱那一刻的 `JSON.stringify(document)`。应用前必须比对，
   否则会把贴唱之后的手工编辑悄悄盖掉。
3. **贴唱不改文档** —— 写文档的只有 `fitApply` 一处（`applyFitPreview()` 只动画层和读数）。

逐字的微调搬进了它该在的地方：`wordDialog` 的 **`wordFromAudio`「从音频检测这一行」**，
仍走 `/api/align/words`（只吸附真实起点，不伪造时间）。

> **写文件只有一个出口**：`/api/save-as`。它现在管四种载荷 —— 歌词文档、`.saltproj`、
> 分析 JSON、批量导出 ZIP（二进制）。**出口一多，就会有一条又被写成页面 blob 下载**，
> 而那个在打包窗口里永远静默（v0.15.0 修过导出歌词，v0.21.0 又抓到两处）。

## 六、`projectDialog` 工程的保存位置（v0.17.0）

| 元素 | `id` | 作用 |
|---|---|---|
| 弹窗本体 | `projectDialog` | 首次启动（没有保存路径时）自动弹出 |
| 路径输入框 | `projectPath` | 预填建议值，可直接粘路径 |
| 就地提示 | `projectState` | **写错路径时的报错就显示在这里**（弹窗背后是状态行，只写那儿等于没提示） |
| 浏览… | `projectBrowse` | 弹**系统**文件夹选择框（用户点了才弹） |
| 稍后再说 | `projectLater` | 本次会话不再问；下次启动仍会问 |
| 用这个文件夹 | `projectUse` | 记住路径，并给已经导入的内容**补建**工程 |

同一套元素在「检查与工程」页也有一份入口：`#projectRoot`（当前路径）+ `#projectCount`
（本次会话建了几个）+ `#projectChange`（再打开上面那个弹窗）。

三条硬规则（都有断言钉着，改之前先看 `tests/test_web_pages.py`
的 `test_the_project_library_has_one_hook_per_rule` 与 `test_the_project_dialog_is_declared_before_its_script`）：

1. **弹窗必须写在 `<script src="/projects.js">` 之前** —— `<script src>` 阻塞解析，
   写在后面 `bind()` 拿到 `null`，按钮就是死的（曲库页"取消/应用"的老病）。
2. **`projects.js` 必须在 `studio.js` 之前加载** —— 它是顶层 `const`，
   `studio.js` 顶层就会引用它（顺序反了会撞 TDZ）。
3. **`.projectBox` 不要给 `dialog` 写 `display`** —— 作者样式会压过引擎的
   `dialog:not([open]){display:none}`（v0.13.3 的"关不掉的框"）。没必要就别碰它。

> 退出流程（`#exitApp`）在这一版变成：`Project.decideExit()`（**同步**问两次）
> → `forgetSession()`（**必须在第一个 `await` 之前**）→ `Project.finishExit()` → `/api/exit`。
> 顺序有静态断言，`tests/web_dom_check.js` 也依赖"点完立刻读 localStorage 已经被清掉"。

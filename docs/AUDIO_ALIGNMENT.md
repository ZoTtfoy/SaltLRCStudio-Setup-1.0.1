# 音频与双轴对齐

## 本机启动

无 AI 依赖也能使用真实波形、双轨拖动、语言脚本识别、声音起点微调。安装 Python 3.10+，双击 `start.bat`。

在项目目录运行以下命令安装默认语音识别及统计语言识别，并下载模型：

```powershell
powershell -File .\setup-ai.ps1
```

脚本只创建项目内 `.venv/` 与 `models/`。模型首次下载需要联网；应用运行时只读取本机模型，音频不上传。下载失败可以重试。基础引擎是 faster-whisper base，多语言、CPU INT8；音乐尤其带伴奏时，准确率低于专门歌词模型。4GB 显存设备默认 CPU，避免显存不足；可在已配置 CUDA 库后用 `python -m saltlrc serve --device cuda`。

HeartTranscriptor 可选安装（模型较大、CPU 较慢）：

```powershell
powershell -File .\setup-ai.ps1 -Engine heart
```

支持 `python -m saltlrc serve --models D:\Models` 指定模型根目录。根目录下应含 `faster-whisper-base/model.bin` 或 `HeartTranscriptor-oss/config.json` 和完整模型权重。安装脚本通过官方 Hugging Face 仓库下载。依赖与模型权重不纳入 Git 备份。

## 工作流

1. 添加同名歌词和音频，或导入文件夹。浏览器 Web Audio 解码，绘制左右声道峰值；全部处理在本机。
2. 主轨与翻译轨有独立开始/结束时间。拖动两条轨道的左边界调整开始，右边界调整结束，内部竖线调整逐字时间。取消「双轴联动」可独立编辑；双轴同步按钮将中文句首移动到日语句首。文字时间输入是等价的精确操作。
3. 自动识别文本语言：假名/韩文脚本提供强证据；纯汉字和纯拉丁短句仍标注不确定。安装 langid 后混合/拉丁长文本使用统计分类器。音频语言由 ASR 自动检测，或手动指定。
4. 选择演唱轨：日语演唱通常对应「翻译轨」。自动模式优先匹配 ASR 检测的语言；无法确定时，存在翻译则先选翻译。可手动改正。
5. 选择语音引擎分析。服务先将浏览器生成的 16kHz mono PCM16 输入交给独立进程；UI 显示运行/失败/完成，可取消。最大 20 分钟音频，单任务，30 分钟超时。任务完成/取消后清理临时音频；服务正常退出也清理。
6. 识别得到带时间的文字片段，按原歌词顺序做保序文本匹配。候选区显示旧/新句首、匹配率、失败原因，可逐句试听。匹配不足 80%、重叠或移动超过 30 秒不默认勾选。重复副歌、译文异文、ASR 漏句等仍可能误匹配，需要试听。
7. 选择候选再应用。分析期间若歌词变更，拒绝应用过期结果。支持撤销；保存工程持久化独立双轨与最近应用的对齐记录。

## 中文与日文的分词口径

日语演唱的声学边界直接对应日语文字，不直接对应中文译词。实现仅用真实 ASR chunk 的开始/结束时间构造原语言词块，同一个 chunk 内的多个汉字或假名会保留为一个整体，不平均分配。

联动应用日语时间时，中文句首跟随，已有中文逐字时间只做整体平移，保留原节奏；这不是中文语义对齐。没有中文逐字时间时不会自动生成伪逐字轴，Salt 导出继续提示补齐。可以在两轨逐字编辑器中按语义选择相应起止时间。要让中文每个词组自动对应日语语义，还需要独立翻译/跨语言语义对齐模型，当前版本未实现。

## 声音起点微调的限制

基础模式用 20ms 帧计算 RMS 能量，在原句首附近（默认 ±1500ms）寻找稳定声音起点。它可以用于原轴基本正确的录音微调，但不识别人声，不知道歌词，可能吸附到鼓点。所有此类候选都需要主动勾选。它不替代语音识别，整首静音/无起点时不会输出虚假结果。

## 智能贴唱（v0.22.0，`saltlrc/fit.py`）

上面那节「声音起点微调」是**逐字细化**用的老口径（`acoustic.py`，现在只服务
逐字编辑器的「从音频检测这一行」）。整首的行级对齐走的是另一条线：

**识别**（`analyse()`）

| | 旧（`acoustic.py`） | 新（`fit.py`） |
|---|---|---|
| 阈值 | `max(.012, 20%分位×2.5, 峰值×.08)` 绝对值 | **中位数 + 3×MAD**（全是相对量）；静音地板相对**峰值** |
| 起始判据 | 任何一次能量上升 | **对数能量的正向增量**（positive log-energy flux），且为局部最大 |
| 是不是人声 | 不判断 → 鼓点/掌声/换气全算 | **浊音度代理**：500 Hz 一阶低通能量占比 ≥0.55，且持续 ≥60 ms |

没有 numpy，所以"人声 vs 打击乐"用一个极便宜的**一阶 IIR 低通**做代理：
元音低频强，镲片/气声/鼓的"嘶"不是。帧长 20 ms、步长 10 ms（重叠一半）。

**对齐**（`fit_lines()`）：所有行在 (行 × 候选起点) 网格上做**一次 Viterbi**，
走一条**单调路径**。代价单位统一为"毫秒当量"：

```
代价(候选) = 离最近人声起点的距离（封顶 500 ms）
           + 移动量 × 0.34（软约束）
           + 落在"长段无人"区间（≥1200 ms 无起点）的 700 ms 惩罚
           + 保持原时间的 30 ms（否则等价选择会原地不动）
转移代价   = |本次行距 − 原行距| × 0.5（保节奏形状）
硬约束     = 后一行句首必须明显晚于前一行（≥250 ms）
```

* 证据弱的行会被**邻行架住**，不会自己跳走；
* 「整首统一偏移」与「逐行微调」在数学上是同一条路径的两个特例；
* 路径回溯时任一环接不上 → **整首退回原时间**（宁可不动，也不给某行编时间）。

**句尾**取行内最后一段浊音的结束（3 帧迟滞，换气不切断），再补 250 ms 尾巴；
找不到就保留原句尾。

**粒度与边界**：只贴**整行**（句首 + 句尾），不动逐字；整行移动时逐字轴整体平移，
相对间距不变。真实值夹具 `tests/test_fit.py`（14 项）、真 HTTP `tests/test_align_routes.py`、
页面接线 `tests/web_align_check.js`（26 项）。识别口径与代价函数的完整说明另见
`saltlrc/fit.py` 模块头。

## 输出约定

Salt/SPW `.lrc` 仍固定中文主轨承担逐字时间、显式句尾；日语第二行只有同一条句首。两轨独立时间不同会阻止 Salt 导出，需同步；普通 LRC 可以输出独立句首。翻译轨逐字信息保存在工程里，Salt 导出不会带出。

## 验证边界

当前开发环境禁止从 PyPI 下载，因此真实 faster-whisper / HeartTranscriptor 推理尚未在此环境执行。已提供实际调用适配器、显式安装脚本、模型状态检查、无模型错误提示；自动化测试覆盖候选匹配、两轨应用、音频能量、任务进程与 HTTP 流程。合成节拍示例只验证波形和能量微调，不能代表歌词识别质量。

HeartTranscriptor 官方建议先分离人声以提高转写效果；当前未自动执行 Demucs。可自行将人声轨作为分析音频。
